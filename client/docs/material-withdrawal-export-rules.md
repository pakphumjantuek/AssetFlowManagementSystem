# ข้อกำหนดการส่งออกใบเบิกวัสดุ

## กฎแบ่งหน้า (ปรับล่าสุด)

- สูงสุด 6 รายการต่อหน้า และตรวจความสูงจริงด้วย QuestPDF ก่อนจัดหน้า หากชื่อยาวให้ลดจำนวนรายการจนแบบฟอร์มลงหน้าเดียวได้
- ทุกหน้ามีหัวเอกสาร เลขใบเบิก วันที่ ข้อมูลผู้เบิก หัวตาราง ข้อความรับรอง และช่องลายเซ็นครบชุดในตำแหน่งเดียวกัน
- ไม่ตัดรายการหรือส่วนท้ายแบบฟอร์มข้ามหน้า ลำดับรายการต่อเนื่องทั้งเอกสาร
- ยอดรวมและจำนวนเงินตัวอักษรเป็นผลรวมของรายการในหน้านั้น ไม่แสดงยอดรวมทั้งเอกสารซ้ำทุกหน้า
- ช่องเพื่อนำไปใช้ในกิจการของใช้หน่วยงานจากเอกสารจัดซื้อ แยกจากช่องสังกัดหน่วยงานที่ใช้ค่าตั้งค่า
- ไม่แสดงบรรทัดอ้างอิงเอกสารตรวจรับและหมายเลขใบตรวจรับ


เอกสารนี้กำหนดแหล่งข้อมูลและข้อความสำหรับใบเบิกวัสดุตามแบบกระดาษที่ผู้ใช้ให้ไว้ ใช้กับ **วัสดุ** ก่อน ยังไม่ครอบคลุมใบเบิกครุภัณฑ์

ไฟล์ PDF สร้างที่ backend ด้วย QuestPDF ผ่าน `POST /api/MaterialWithdrawalExport/{id}/pdf` โดยรับวันที่ที่เลือกและรหัสบุคลากร แล้ว backend ดึงเลขเอกสาร รายการวัสดุ ชื่อบุคลากร ยอดเงิน และค่าตั้งค่าใบเบิกจากฐานข้อมูลเอง

หน้าส่งออกแสดงตัวอย่างจาก PDF ที่ backend สร้างจริงโดยยังไม่จองเลข เมื่อยืนยันดาวน์โหลดจะเรียก `/pdf/issue` เพื่อจองเลขและสร้างไฟล์อีกครั้ง หากเอกสารเคยออกเลขแล้วจะใช้เลขเดิม เมื่อเปลี่ยนวันที่หรือผู้รับของต้องสร้างตัวอย่างใหม่ก่อนยืนยัน ไม่ประกอบแบบใบพิมพ์ซ้ำด้วย HTML ฝั่ง client

หน้ารายการวัสดุของเอกสารจัดซื้อส่งออกได้โดยตรงผ่าน `POST /api/MaterialWithdrawalExport/procurement/{id}/pdf` แม้ยังไม่มีใบเบิกวัสดุ โดยใช้รายการทั้งหมดของเอกสารหลักเช่นเดียวกัน

## แหล่งข้อมูลบนใบพิมพ์

| ช่องบนใบพิมพ์ | แหล่งข้อมูล / กฎ |
| --- | --- |
| เลขที่ใบเบิก | `ProcurementRecord.withdrawal_document_no` ของเอกสารหลัก |
| บัญชีเล่มที่ / เลขที่ | `ProcurementRecord.export_book_number` และ `export_serial_number`; จองครั้งแรกตอนยืนยันดาวน์โหลด และคงเลขเดิมเมื่อส่งออกซ้ำ |
| วันที่บนใบเบิก | ให้ผู้ใช้เลือกวันที่ในหน้าส่งออก ไม่ผูกกับฟิลด์วันที่ของ `ProcurementRecord` |
| “ตั้งแต่วันที่” ในข้อความรับผิดชอบ | ใช้วันเดียวกับวันที่บนใบเบิก |
| อ้างอิงเอกสารขออนุมัติ | `ProcurementRecord.decree_document_no` |
| เลขที่เอกสารอีกช่อง | `ProcurementRecord.document_no` |
| ข้าพเจ้า / ชื่อผู้รับของใต้ลายเซ็น | ดึงรายชื่อบุคลากรทั้งหมดให้เลือกตอนส่งออก แล้วใช้ชื่อที่เลือกคนเดียวกันทั้งสองช่อง |
| สังกัดหน่วยงาน / เพื่อนำไปใช้ในกิจการของ | `department_name` ตามค่าหน่วยงานที่ตั้งไว้ในหน้าตั้งค่าเอกสาร; แสดงชื่อเดียวกันทั้งสองช่อง |
| เจ้าหน้าที่พัสดุ | ค่าเริ่มต้น `นางสาวเสาวณีย์ หกประเสริฐ` และแก้ไขได้ในหน้าตั้งค่าเอกสาร |

`MaterialWithdrawal` ใช้เป็นบริบทสำหรับเปิดหน้าส่งออก แต่ไม่ใช้ `MaterialWithdrawal.withdrawal_document_no` หรือ `withdrawal_date` แทนเลขที่ใบเบิกและวันที่ที่ผู้ใช้เลือกในตารางข้างต้น

## รายการวัสดุและยอดเงิน

- แสดงรายการวัสดุ **ทั้งหมดในเอกสารจัดซื้อหลัก** จากรายการรับวัสดุ (`MaterialReceiveDetail`) ไม่จำกัดเฉพาะรายการหรือจำนวนที่คนเบิกใน `MaterialWithdrawal`
- แต่ละแถวแสดงลำดับ ชื่อวัสดุ จำนวนเต็มตามเอกสารจัดซื้อ หน่วยนับ ราคาต่อหน่วย และรวมเงินของแถวนั้น
- รวมเงินของแต่ละแถวใช้มูลค่าของรายการรับวัสดุตามเอกสารหลัก (`MaterialReceiveDetail.total_amount`)
- ช่อง **รวมเงินท้ายใบ** ใช้ `ProcurementRecord.total_amount` โดยตรง และช่อง **จำนวนเงินเป็นตัวอักษร** ใช้ `ProcurementRecord.amount_text` โดยตรง ไม่คำนวณหรือแปลงคำอ่านใหม่จากรายการวัสดุ
- ไม่ใช้คอลัมน์ “เบิกแล้ว” หรือ “ยอดคงเหลือ” มาลดจำนวนหรือยอดเงินบนใบส่งออก
- ตัวอย่างรับ 20 เบิกแล้ว 2 คงเหลือ 18 ราคาหน่วยละ 130 บาท: ใบส่งออกแสดงจำนวน **20** และรวมเงิน **2,600 บาท**
- หากผลรวมของมูลค่ารายการวัสดุไม่ตรงกับ `ProcurementRecord.total_amount` ให้ถือยอดของ `ProcurementRecord` เป็นค่าที่แสดงในช่องรวมเงินท้ายใบ และตรวจสาเหตุของส่วนต่างก่อนใช้งานจริง
- ต้องตรวจว่าข้อมูลรายการรับวัสดุที่ API ส่งกลับมีหน่วยนับครบหรือไม่ ก่อนทำแบบพิมพ์จริง

## ข้อความและลายเซ็น

ข้อความเริ่มต้นด้านล่างใบพิมพ์:

> โดยข้าพเจ้าจะขอรับผิดชอบตามระเบียบกระทรวงการคลังว่าด้วยการจัดซื้อจัดจ้างและบริหารพัสดุภาครัฐ พ.ศ. ๒๕๖๐ ทุกประการ และได้รับสิ่งของตามรายการนั้นไปเรียบร้อยแล้ว ตั้งแต่วันที่ [วันที่บนใบเบิก] หากสิ่งของที่ข้าพเจ้าได้รับไปเกิดการสูญหายขึ้น ข้าพเจ้ายินยอมให้หักเงินเดือนชดใช้ตามที่มหาวิทยาลัยกำหนดจนครบเท่าราคาซื้อ

- ให้แก้ข้อความนี้ได้ในหน้าตั้งค่าเอกสาร โดยคงตำแหน่งวันที่ไว้สำหรับแทรกวันที่จากเอกสารหลัก
- แสดงชื่อผู้รับของตามบุคลากรที่เลือกตอนส่งออก และชื่อเจ้าหน้าที่พัสดุตามค่าที่ตั้งไว้
- เว้นเส้นและพื้นที่ลงลายมือชื่อบนใบพิมพ์

## การตั้งค่าและเลขเอกสาร

- เก็บเล่มปัจจุบัน เลขถัดไป หน่วยงาน เจ้าหน้าที่พัสดุ และข้อความท้ายใบใน `material_export_settings` ผ่านหน้าตั้งค่า โดยผู้ดูแลระบบเป็นผู้แก้ไข
- เก็บเลขที่ออกจริงไว้ที่ `procurement_records` หนึ่งชุดต่อเอกสาร ไม่เก็บซ้ำในแต่ละแถวของ `MaterialReceiveDetail`
- ฐานข้อมูลบังคับคู่ `(export_book_number, export_serial_number)` ไม่ให้ซ้ำ และ backend ใช้ transaction กับ `sp_getapplock` ตอนจองเลข
- การดูตัวอย่างไม่จองเลข การยืนยันครั้งแรกจองเลขและสร้าง PDF ใน transaction เดียวกัน หากสร้าง PDF ล้มเหลว transaction จะ rollback
- การเปลี่ยนเล่มหรือเลขถัดไปในหน้าตั้งค่าต้องไม่ย้อนกลับไปชนเลขที่ออกแล้วในเล่มนั้น
