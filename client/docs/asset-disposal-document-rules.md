# การจำหน่ายครุภัณฑ์ด้วยเอกสาร

## ขั้นตอน

- หน้าครุภัณฑ์หลักของเอกสารจัดซื้อและทะเบียนครุภัณฑ์ทั้งหมดมีปุ่มอัปโหลดเอกสารจำหน่ายทั้งชุด
- หน้าครุภัณฑ์ย่อยอัปโหลดเอกสารเฉพาะรายการที่เลือกได้
- ต้องมีไฟล์ PDF, JPG หรือ PNG ไม่เกิน 10 MB และวันที่จำหน่าย เลขเอกสารกับหมายเหตุเป็นข้อมูลเพิ่มเติม
- เมื่อไฟล์ เอกสาร ประวัติ และสถานะบันทึกสำเร็จครบ จึงเปลี่ยนรายการย่อยเป็น `จำหน่ายแล้ว`
- ทั้งชุดเปลี่ยนเฉพาะรายการย่อยที่ยังไม่จำหน่าย และใช้เอกสารชุดเดียวกัน รายการที่จำหน่ายก่อนหน้าเก็บหลักฐานเดิมไว้
- ชุดที่ไม่มีรายการย่อยสามารถจำหน่ายด้วยเอกสารระดับชุดโดยตรง

## สถานะชุด

- คำนวณจากรายการย่อยที่ใช้งานทั้งหมดของชุด ไม่ใช่เฉพาะหน้าตารางปัจจุบัน
- ยังไม่มีรายการจำหน่าย: `ใช้งานอยู่`
- มีบางรายการจำหน่าย: `จำหน่ายบางส่วน (จำนวนที่จำหน่าย/จำนวนรายการทั้งหมด)`
- ทุกรายการจำหน่าย: `จำหน่ายแล้ว`
- ชุดไม่มีรายการย่อย: ตรวจเอกสารจำหน่ายระดับชุด

## หลักฐานและความถูกต้อง

- เก็บไฟล์ใน `backend/APi/App_Data/asset-disposals` นอกพื้นที่ไฟล์สาธารณะ เปิด/ดาวน์โหลดผ่าน API ที่ต้องล็อกอิน
- เก็บผู้บันทึก วันเวลาบันทึก วันที่จำหน่าย และจำนวนรายการที่ได้รับผล
- ตรวจชนิดไฟล์จากเนื้อหา ไม่ใช่แค่นามสกุล
- ใช้ transaction ป้องกันจำหน่ายซ้ำ และลบไฟล์ที่เขียนแล้วถ้าบันทึกฐานข้อมูลล้มเหลว
- เก็บประวัติจากระบบเดิมไว้และแสดงรายละเอียดเดิมเมื่อยังไม่มีไฟล์เอกสาร
- ขั้นตอนจำหน่ายเดิมที่ไม่มีไฟล์ไม่อนุญาตให้เปลี่ยนสถานะอีกต่อไป
- ไม่ให้เพิ่มรายการย่อยในชุดที่จำหน่ายแล้ว ไม่ให้ลบรายการจำหน่าย หรือใช้ฟอร์มแก้ไขเพื่อเปลี่ยนสถานะจำหน่าย
- ยังไม่มีปุ่มยกเลิกจำหน่ายหรือแทนที่หลักฐาน เพื่อคงเอกสารและประวัติที่บันทึกไว้

## ฐานข้อมูลและการทดสอบ

- Migration `AssetDisposalDocuments` เพิ่มตารางหลักฐานใหม่ ไม่ลบข้อมูลเดิม
- API ใช้ migration อัตโนมัติเมื่อเริ่มระบบตาม Program.cs เดิม
- `tests/asset-disposal` ทดสอบกับ SQLite ชั่วคราว โดยไม่เขียนฐานข้อมูลจริง รวมการจำหน่ายบางส่วน ทั้งชุด ชุดไม่มีรายการย่อย เอกสารร่วม การจำหน่ายซ้ำ และ rollback ไฟล์/สถานะ
